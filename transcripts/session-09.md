  ## 1. Audit the existing UI                                                   
                                                                                
  Before changing anything:                                                     
                                                                                
  - Read CLAUDE.md and existing design conventions.                             
  - Inspect the latest dev branch.

  ## 2. Establish a motion design system                                        
                                                                                
  Create a consistent motion language using reusable design tokens.             
                                                                                
  Suggested starting guidelines:                                                
                                                                                
  - Microinteractions: 100–180ms.                                               
  - Hover transitions: 150–250ms.                                               
  - Expand/collapse transitions: 200–300ms.                                     
  - Page or section entrances: 250–450ms.                                       
  - Small hover elevation: approximately 2–4px.                                 
  - Use natural ease-out curves for entrances.                                  
  - Use restrained easing for state changes.                                    
                                                                                
  Treat these as starting points, not rigid rules.                              
                                                                                
  Prefer GPU-friendly transform and opacity animations.                         
                                                                                
  Avoid unnecessary layout-triggering animations.                               
                                                                                
  ## 3. Homepage interactions                                                   
                                                                                
  Make the landing page feel dynamic and engaging.                              
                                                                                
  Consider:                                                                     
                                                                                
  ### Hero section                                                              
  - Gentle entrance animation for headline, description, and CTAs.              
  - Subtle staggered entrance of hero content.                                  
  - Refined interaction on primary and secondary CTAs.                          
  - Tasteful interaction in any existing calculator preview.                    
                                                                                
  ### Feature cards                                                             
  - Subtle hover lift.                                                          
  - Gentle shadow or border emphasis.                                           
  - Smooth icon transitions where meaningful.                                   
  - Clear visual feedback for clickable cards.                                  
  - Preserve keyboard focus states equivalent to hover effects.                 
                                                                                
  ### Scroll reveals                                                            
  - Reveal important sections as users encounter them.                          
  - Use restrained opacity and small vertical transforms.                       
  - Avoid large sliding distances.                                              
  - Do not repeatedly animate sections every time they enter the viewport.      
  - Ensure content remains visible if JavaScript or animation support is        
  unavailable.                                                                  
                                                                                
  ### Navigation                                                                
  - Smooth link-state transitions.                                              
  - Clear active-page indication.                                               
  - Tasteful hover and focus feedback.                                          
  - Accessible mobile menu transitions where a menu exists.                     
                                                                                
  ### Calls to action                                                           
  - Responsive hover, focus, and pressed states.                                
  - Subtle elevation or background transitions.                                 
  - Avoid excessive scaling, bouncing, glowing or continuous pulsing.           
                                                                                
  ## 4. Calculator interactions                                                 
                                                                                
  The calculator is a financial tool, so clarity and speed are more important   
  than decorative animation.                                                    
                                                                                
  Introduce appropriate feedback for:                                           
                                                                                
  - Input focus and validation.                                                 
  - Fixed-rate versus ARM selection.                                            
  - Loan-term selection.                                                        
  - Down-payment mode switching.                                                
  - Advanced settings expansion and collapse.                                   
  - PMI and optional cost toggles.                                              
  - Recalculated monthly estimates.                                             
  - Cash-to-close results.                                                      
  - Saved scenarios.                                                            
  - Amortization views.                                                         
  - Charts and comparison results.                                              
                                                                                
  Do not animate every digit on every keystroke.                                
                                                                                
  Avoid flickering or jumping numbers.                                          
                                                                                
  For changing financial values, prioritize stable layouts and readability.     
  Consider a subtle highlight or short transition only when a meaningful result 
  changes.                                                                      
                                                                                
  Never animate a stale financial estimate as though it were newly calculated.  
                                                                                
  ## 5. Data visualization

  - Smoothly transition between valid data sets when inexpensive.

  - Ensure the underlying numerical data remains available.

  Respect prefers-reduced-motion throughout the application.                    
                                                                                
  When reduced motion is enabled:                                               
  - Disable decorative entrance animations.                                     
  - Remove parallax and unnecessary movement.                                   
  - Keep immediate, understandable state changes.                               
  - Preserve clear hover, focus, active, and validation feedback.               
                                                                                
  Ensure:                                                                       
  - No flashing effects.

  - No content hidden behind unfinished animations.                             
  - No keyboard focus loss.                                                     
  - No unexpected page movement.                                                
  - No layout shifts caused by hover effects.                                   
  - No important information communicated by animation alone.                   
  - Touch devices do not depend on hover interactions.                          
                                                                                
  Maintain WCAG AA accessibility expectations.                                  
                                                                                
  ## 8. Performance requirements

  approach would work.                                                          
                                                                                
  Avoid broad transition-all rules.                                             
                                                                                
  Use will-change sparingly.                                                    
                                                                                
  Make sure animations do not interfere with:                                   
  - React rendering.                                                            
  - Calculator inputs.                                                          
  - Financial calculations.                                                     
  - Page loading.                                                               
  - Core Web Vitals.                                                            
  - Printing.                                                                   
  - Screen readers.
